# 创建与管理 API Key

API Key 是客户端调用 Micro Build AI 的凭证。持有完整密钥的人可能使用你的可用额度，请像保护密码一样保管它。

## 创建密钥

1. 登录 [Micro Build AI](https://ai.mbuild.top/)。
2. 打开「API Key」或「API 密钥」页面，选择创建。
3. 输入用途名称，例如 `my-codex`、`my-claude-code`、`my-gemini`、`my-antigravity` 或 `my-cherry-studio`。
4. 如果页面提供分组或权限选项，选择管理员分配给你的可用范围。模型权限与此有关；不清楚时先联系管理员。
5. 如果当前页面支持额度、有效期或访问限制，按需要设置；初次配置时确认这些限制不会拦截自己的请求。
6. 保存后按界面提示复制完整密钥，保存在密码管理器中。

不同部署版本的字段与按钮可能略有差异，以 Micro Build AI 当前页面为准。

## 复制并填写到客户端

- 复制完整值，不要把 `sk-****` 之类的掩码当成真实密钥。
- 客户端的 API Key 输入框只填密钥，不加 `Bearer `、引号、空格或换行。
- 手动调用 OpenAI 兼容接口时，通常使用 `Authorization: Bearer <密钥>`；Gemini 原生客户端使用自己的认证格式，例如 `x-goog-api-key`，按对应教程配置即可。
- Base URL 与模型 ID 是另外两项信息，不能填到密钥输入框里。

## 为每个工具使用独立密钥

建议为每个工具分别创建密钥，方便识别使用记录，也方便单独停用某个工具的访问。密钥额度或有效期属于访问限制，不等同于账户余额；即使密钥有效，余额不足仍可能导致调用失败。

在使用记录中按密钥名称查看请求，检查有没有不认识的调用。

## 修改、停用与删除

在密钥列表中选择对应项，按当前页面提供的操作修改名称、限制或状态。

- **停用**：如果页面提供停用开关，可先停止该密钥的调用，再处理问题。
- **删除**：删除后，使用此密钥的客户端会失去访问权限；不要把删除当成退出登录。
- **更换**：创建新密钥，在相关客户端替换并验证成功后，停用或删除旧密钥。

如果怀疑已经泄露，优先立即停用或删除旧密钥，再创建新密钥并检查使用记录。

## 保管密钥

- 不把真实密钥写入代码仓库、公开文档、工单、聊天消息或截图。
- 不在前端网页代码中嵌入密钥，也不把密钥放进 URL 参数。
- 不与他人共用个人密钥；每个人使用自己的账号和密钥。
- 需要协助时，只提供密钥名称或掩码，附上时间、模型、错误信息和 Request ID。

遇到鉴权失败，按[401 排查](/faq#unauthorized)检查；余额问题见[余额与权限排查](/faq#balance)。
